# Migrate the historical snapshots into the new note structure

## Question

One-time backfill: convert the existing hand-maintained `Laboratory test.md` (5 snapshots, 2020–2025 —
blood/biochem/antigen/urine panels + vitals, each value carrying a sex-specific reference range, unit, and a
manual trend arrow, plus prose) into the new frontmatter-first notes decided in
[Decide the data model and source of truth](02-data-model-source-of-truth.md):

- `health/labs/<report-date>.md` — one per visit (5 notes), raw canonical values only, no arrows
  (dates = **report dates**, per ticket 06).
- `markers/<id>.md` — one per marker, derived from the old **reference-range columns** (unit, `alt_factor`,
  panel/concern, sex+age-banded `ranges`, two-tier `optimal_*` + `direction`, `formula` for derived,
  `normal:` for qualitative; BP = two paired markers).
- `profiles/<person>.md` — the single current user.

Decisions this ticket must make/do:
- **Script vs manual pass** — one-off parser over the old markdown table, or a guided pass through the
  ticket-06 entry modal ×5? (Deriving the `markers/` notes is the harder half — the entry modal assumes
  markers already exist.)
- **Marker derivation** — how the old reference-range / unit columns map onto `markers/` note fields;
  where qualitative and BP rows in the old table land.
- **Unit canonicalisation** — old values may be in `alt_unit`; convert to canonical on the way in
  (same rule as ticket 06 entry).
- **Verification** — confirm the migrated notes reproduce the old table's values + arrows before deleting.

Resolved when the 5 visit notes + `markers/` + `profiles/` notes exist and verify against the old table.
Records what was done and any facts later work depends on. **`Laboratory test.md` is retired (backup then
delete) only after this verifies** (per ticket 03). Blocked by the data model (02).

## Resolution

**EXECUTED** (this map's one plan-not-do exception, per the user — build-flavored task that unblocks real use).
Generator: `scratchpad/migrate.py` (parses the source, emits notes, self-verifies).

**Location (per user):** everything under **`09 about-me/`** in the vault, beside the source note —
`09 about-me/health/labs/`, `09 about-me/markers/`, `09 about-me/profiles/`. The plugin's configurable
`paths` (ticket 09) point here.

**Written & verified:**
- **5 visit notes** — `health/labs/{2020-07-20, 2022-08-02, 2023-08-24, 2024-07-23, 2025-07-23}.md`
  (`type: lab-visit`, `person: self`, `date:`, flat marker-id keys; arrows dropped, skipped tests omitted,
  qualitative kept as strings).
- **59 marker notes** — `markers/<id>.md` (blood 30 · biochemical 14 · antigen 4 · urine 11),
  id = snake_case of the source Test (wikilink **target** for a
  stable id); `name`/`aliases`/`type`/`unit`/`panel`/`concern`/`ranges` (sex-banded where the source gave
  `M:`/`W:`), qualitative markers carry `normal:`. **Body blurb = the clinical description** pulled from the
  note's Reference glossary tables ("explain in place" tooltip source).
- **`profiles/self.md`** — `sex: m`, `blood_type: "A, Rh+"` (from the ABO+Rh row).
- **Eyeball Base** — `health/Lab visits.base`, **auto-generated by the script** with **all 59 markers** as
  columns (grouped by panel, visits as rows) so it can't drift from the notes.

**Verification:** the migration script does a **round-trip** (parse → write → re-read → diff) = **0 mismatch
over 236 values**, PLUS **source spot-checks** (uric_acid, HDL, LDL, cholesterol_total, psa_total, cea) and a
**per-panel completeness tally** (blood 30 · biochemical 14 · antigen 4 · urine 11).
**Two parse bugs the round-trip could NOT catch — round-trip only proves write/read fidelity, not
parse-vs-source:**
1. Obsidian escapes `|` inside table cells as `\|`, mis-splitting the wikilink-with-alias rows
   (uric_acid/HDL/LDL) → fixed the row splitter; spot-checks confirm.
2. Panel headings were matched by **exact emoji string**, so `🦠 Antigen` silently failed and the **entire
   antigen panel** (HbsAg/HbsAb/PSA/CEA — markers *and* values) was dropped → fixed to keyword-match bounded
   before the `# Reference` glossary; the panel tally + antigen spot-checks now guard it.
3. A markdown-escaped `\>` from the source (`hbsab: "\> 1,000"`) became an **invalid YAML escape inside double
   quotes**. PyYAML tolerated it; **Obsidian's stricter YAML rejected the whole frontmatter block**, silently
   dropping the 2022 & 2023 visit notes from every Base (they showed no `type`/`date` in `metadataCache`) →
   fixed by unescaping backslashes in cell values **and** writing string values in **single quotes** (YAML
   single quotes do no escape processing). Diagnosed by querying Obsidian's own `metadataCache` via the CLI —
   **the definitive check is Obsidian's parser, not PyYAML or the script's round-trip.** Confirmed: all 5 notes
   now resolve as `type: lab-visit`.

**Refines ticket 03's "retire (delete)":** `Laboratory test.md` is **NOT deleted.** Its lab tables + reference
glossary are now migrated (redundant), but it still holds the **planner prose** — "What to look for in future
test" (optional-test backlog: ApoB, HbA1c, Homocysteine… with costs/URLs) + the yearly "Health check package
analysis" — which nothing absorbs yet. Kept in place; feeds the **add-test/package planner** fog.

  grouping the vision/flagging use (lipids, glucose, liver, kidney, …).
- 9/55 markers have no blurb (not found in the glossary) — fill by hand.
- Dual-unit `alt_factor` not populated; two-tier `optimal_*` personal targets not set — author as desired.
- `blood_type` stored verbatim as "A, Rh+" — tidy to taste.
